# 理理理 · 产品与交互定义

> 用途:开发对齐的唯一口径。每页交互逻辑由产品口述、逐页确认后固化在此;开发中遇到歧义以本文件为准。
> 结构:先是主链路定义,然后逐页(Home → 输入 → Sandplay → Keep → Spaces)。

## 主链路定义(2026-08-27 确认)

1. **Home** → 点 Create
2. **输入**:语音优先,也支持打字(现 F2)
3. **Sandplay(直播间形态)**:背景是 AIGC 视频 —— 用户的 story 经 LLM 解析成 prompt → 交给 VLM 生成 → 出现在流式对话界面的舞台槽位里
4. **进沙盘第一步:选角色** —— 从 LLM 识别出的这个故事中的角色里,选一个要带入的
5. **进入直播间**:观看沙盘模拟;过程中用户**以带入角色的视角**继续推进对话

注意:「选带入角色」是沙盘体验内的第一步,不是独立大改;现代码中的沙盘尚未包含此步。

## F1 · Home(My Stories)

大板块:Header(标题 + 右上角入口)/ Gallery / 底部 Create 按钮 / 数字人(companion)。

### Gallery(故事长廊)

- **两个状态**:空状态 / 有若干 story 的状态
- 当前 demo 实现并调好的是**有 story 的状态**:纵深扇形卡堆,拖/滑翻牌,点侧卡吸附到最前,点前置卡进该故事的沙盘;前置卡下方联动显示标题 + 日期
- 空状态:虚线裱卡槽位 "your first story"(代码里已有,交互未细调)

### 数字人(companion,右下角小动物)

- 定义:用户的数字人 —— 一个小动物形象,是**用户最柔软的性格特征的化身**
- 交互:点击 → 进入**数字人的编辑**
- 现状:代码里点 companion 目前等同于 Create(开新故事),编辑页未做 —— 待改

### Create 按钮

- 圆角矩形按钮,开一个新的沙盘 Story → 进入输入页
- 现状:已实现("Create the sandplay")

### 右上角:别人的 Gallery

- "Visit other spaces" → 看别人的 Gallery
- 现状:界面已有(F5 Spaces),**还没开始调**

## F2 · 输入页(Speak It)

- **核心形态**:像信纸一样,实时呈现用户语音输入的内容;故事在信纸上写完后,用户确认 → 进入下一步(沙盘演绎)
- **输入方式**:语音优先;可切换为打字输入
- 现状:已实现 —— 语音伪实时转写逐词上屏(信纸式排版),"Type it" 切打字,`Done` 确认,确认前有沉淀态

## F4 · 沙盘演绎(Sandplay / 直播间)

两个大板块,先后发生:

### 板块一:选带入角色

- 用户从 LLM 识别出的**这个故事中的角色**里,选一个自己要带入的角色
- 选完才进入直播间

### 板块二:直播间(情景演绎 + 群聊交互)

- 界面形态:类似直播间 —— 背后是该故事的 AIGC 情景演绎视频,对话以流式浮层盖在画面上
- 用户**以所选角色的视角**在群聊里交互,推进故事
- **群聊成员 = 这个故事中出现的人物 Top 3**(优先级最高的 3 个;不定 Top 5,太难)
- 每个角色由**独立的 LLM session** 扮演,各自决策发言或沉默(呼应后端契约:人设提取上限 3 个、SSE 多角色并发流式输出)

### 现状差距

- ~~没有「选带入角色」这步~~ **板块一已实现(mock)**:F2 确认 → PickRole 选角(提取中有 shimmer 加载态)→ 以所选角色身份进直播间(气泡带角色名 + 头像,输入框 "Speak as {name}…")
- 板块二细节待优化:AIGC 视频未就绪时的友好加载态("演绎中"提示等)、发言者从常驻房间角色换成故事 Top 3 角色
- 用户在群聊里目前是"自己",尚未以带入角色的身份发言 → 同上,板块一已解决身份展示,AI 侧阵容待板块二处理
