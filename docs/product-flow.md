# 理理理 · 产品与交互定义

> 用途:开发对齐的唯一口径。每页交互逻辑由产品口述、逐页确认后固化在此;开发中遇到歧义以本文件为准。
> 结构:先是主链路定义,然后逐页(Home → 输入 → Sandplay → Keep → Spaces)。

## 主链路定义(2026-08-27 确认)

1. **(真后端模式)Auth 登录/注册** → Home;演示模式有一键跳过
2. **Home** → 点 Create
3. **输入**:语音优先,也支持打字(现 F2)
4. **故事解构**:一次 LLM 调用把口述拆成「场景」+「角色」两份产物(见下「解构」一节)
5. **等候室**:等 AIGC 视频生成;等待活动 = **头像消消乐**(五位角色的头做棋子,无倒计时/失败态),每消掉一组在顶上换一句正念短句 / 名人名言;视频就绪 → 收到「回信」→ 拆开 → **幕布拉开转场** → **首映页先看演绎视频**
6. **进沙盘第一步:选角色** —— 从解构出的角色里,选一个要带入的
7. **阶段二 · 直播间群聊**:顶部演绎视频 + 底部群聊,用户**以带入角色的视角**重演这一天

注意:「选带入角色」已实现(PickRole);「Auth」只在真后端模式下出现。

## 故事解构(2026-08-28 定义)

口述是含糊、重复、乱序的;解构这一步在**整条链路的最上游**,后面每一环都吃它的输出 ——
所以它产出什么,直接决定后面演成什么样。一次 LLM 调用同时产出场景与角色,
避免分两次调用导致「画面里的人」和「群聊里的人」对不上。

| 产物 | 给谁用 | 作用 |
|---|---|---|
| `scene.setting/mood/beats` | VLM | 生成情景演绎视频的脚本(beats = 看得见的画面,不含心理活动) |
| `appearance` | VLM | 画出这个角色,保证画面里的人 = 群聊里的人 |
| `name` / `profile` | PickRole | 用户据此选「带入谁」 |
| `voice` | 阶段二群聊 | 这个角色**怎么说话**(节奏/用词/回避什么),三个角色不许撞车 |
| `stance` | 阶段二群聊 | 这个角色**要什么、站哪边** —— 有分歧,群聊才有张力,不会齐声附和 |

两条关键规则:

- **含糊的复数要拆开**:「有些同事不太友好」可能藏着两种完全不同的压力(甩活的 / 让你显得不如人的),
  拆成两个可分辨的角色;但只在口述确实支撑时才拆。
- **`voice` 必须是「会说话的声音」**:实测踩过 —— 模型会把 `appearance` 的电影感带进 `voice`,
  写出「从不出声,只以空椅子暗示」,该角色进群聊后就再也不说话了(只吐 `*空椅子吱呀*` 这类舞台指示)。
  prompt 已明确:每个角色都是群聊里**会开口的参与者**,现实中没说过话的存在也要给一副能说话的嗓子。

## 两个阶段(2026-08-28 定义)

说完故事之后不是直接进群聊,而是**两个逻辑完全不同的阶段**,中间由「视频就绪」这个外部事件切换。
两套逻辑不可混用:

| | 阶段一 · 旁观者 | 阶段二 · 群聊重演 |
|---|---|---|
| 几个声音 | 一个 | 多个(故事 Top 3,用户带入其一) |
| 站在哪 | 故事**外** | 故事**里** |
| 谈什么 | 这件事**说明什么**(spread the idea / mindset) | 重演**这件事本身** |
| 谁推进 | 用户 + 视频进度 | 用户 + 节奏状态机 |
| 何时结束 | 视频就绪(外部事件),不由对话逻辑决定 | 用户 Keep / 三轮无互动 |
| 机制 | 无 SILENT、无轮内可见、无 2 人上限 | 全套群聊机制 |

### 阶段一 · 旁观者(`/api/llm/godfather`)

- 定位:**不是故事里的角色**,是听完的人。职责是把这件事的形状说出来,不是演剧情。
- 固定性格(与每次提取的故事人设不同):不复述、不诊断、不用治疗腔、不许诺「会好起来的」、
  不以「听起来你…」开头;一次只给**一个**想法,45 字以内。
- 四个 mode:`open`(故事刚讲完)/ `respond`(用户回话)/ `linger`(视频慢、用户沉默时再补一句)/
  `handoff`(视频就绪,一句话把人送进重演,然后退场)。
- 因为由外部事件结束,**任何时刻都要可被打断** —— 不能写成固定长度的脚本。

### 阶段二 · 群聊重演(`/api/llm/turn`)

节奏规则见下面 F4 一节。这一阶段的**核心是「重演」而不是「复述」**:

- 转写是「第一次是怎么发生的」,**不是不可更改的剧本**。
- 用户带入角色后可能说出与原故事**完全不同**的话 —— 这正是沙盘的意义:
  看看换一种说法,事情会怎么走。
- 因此角色必须**跟着新分支走**,绝不能把用户拉回「可你当时明明说…」。
  **性格固定,剧情自由**;新分支可能更好也可能更糟,不强行圆成温暖结局。

### 现状(诚实标注)

- 两条服务端链路已实现并用真实故事实测通过:解构 → 阶段一四个 mode → 阶段二(含分支实测)。
- **等候室改版(2026-08-29 产品确认)**:等待期不再有旁观者陪聊 LLM,Reflect 帧 = 舞台口闭合幕布
  + 小游戏区(2026-08-29 二改:头像消消乐,components/game/HeadMatch.tsx;文案池 lib/mindful-quotes.ts,
  预置正念短句 + 公域名言,每消一组随机换一句,一轮之内不重复);等待的就是「VLM 视频返回」这个外部事件,就绪后落一封「回信」,
  拆开 → CurtainVeil 幕布拉开 → Premiere 首映页(先看视频)→ PickRole 选角 → F4 群聊(顶视频底问答)。
  godfather 接口与上文 prompt 约定保留,产品如重启陪聊可直接接回。

### 未定(需产品拍板)

1. 阶段一那个声音的**对外名字**:内部代号 godfather,但中英文都带教父/黑帮联想,不适合直接露出。
2. 它与 F1 右下角**数字人(companion)是不是同一个角色** —— 若是,IP 可统一,但数字人当前定义是
   「用户最柔软的性格特征的化身」,与「站在故事外的旁观者」不完全一致。
3. 阶段一与 PickRole 的**先后**:当前建议 F2 → 阶段一(等视频)→ PickRole → 阶段二,
   因为阶段一正好覆盖等待时间,且 PickRole 紧挨着它配置的那场群聊。

## F4 · 沙盘演绎(Sandplay / 直播间)

两个大板块,先后发生:

### 板块一:选带入角色

- 用户从 LLM 识别出的**这个故事中的角色**里,选一个自己要带入的角色
- 选完才进入直播间

### 板块二:直播间(情景演绎 + 群聊交互)

- 界面形态:类似直播间 —— 背后是该故事的 AIGC 情景演绎视频,对话以流式浮层盖在画面上
- 用户**以所选角色的视角**在群聊里交互,推进故事
- **群聊成员 = 这个故事中出现的人物 Top 3**(优先级最高的 3 个;不定 Top 5,太难);用户带入其一,其余为 AI
- 每个角色由**独立的 LLM session** 扮演(呼应后端契约:人设提取上限 3 个、SSE 多角色并发流式输出);一轮之内**串行生成、后者可见前者本轮发言**,避免互相重复/打架

### 群聊节奏规则(2026-08-28 确认)

1. 开场 AI 暖场几句 → **停下来等用户**(18s)
2. 用户沉默 → AI 之间续聊一轮 → 再等(18s)
3. 仍沉默 → 一位 AI **点名邀请**用户带入的角色(必须开口)→ 再等(20s)
4. 三轮仍无互动 → **弹窗问用户要不要结束**(Keep this story / Stay a little longer)
5. 用户一旦开口 → **所有 AI 都必须思考如何回应用户**,回应后节奏重置回第 1 步的等待
6. 防打架/防卡死:每轮最多 2 位 AI 开口、每段沉默期只续一轮、prompt 禁止争论与复读、允许沉默

### 旁白 · 上帝视角(2026-08-29 产品确认)

- 群聊里除故事角色外,还有一个**客观陈述**的声音(根据其他人的聊天做中立旁观)
- **插入时机完全由后端判断**:回复流里带 `speakerId: "narrator"`(lib/types.ts `NARRATOR_ID`)的一条即可
- 前端渲染:聊天区顶部钉一条**样式完全不同的深底气泡**(ink-blue 底 + 奶油斜体 +「旁白·上帝视角」标签),
  不进普通气泡流、无头像;新旁白到达时替换上一条;流式期间在横幅里逐字吐

### 对话链路全真实 LLM(2026-08-28 起)

- 人设提取与群聊发言**不再有任何 mock 兜底**;失败只在界面给重试/日志,方便观察 LLM 真实行为
- 模型:`kimi-k2.5`(openai-next 平台);`kimi-k3` 是 reasoning 模型,单轮 30s+ 不适合对话场景
- mock 声线库(lib/mock/dialogue.ts)已删除

### 现状

- 板块一已实现:F2 确认 → PickRole 选角(真 LLM 提取,提取中 shimmer;失败给"Try again"重试,不塞假数据)→ 以所选角色身份进直播间(气泡带角色名 + 头像,输入框 "Speak as {name}…")
- 板块二已实现:群聊阵容 = 故事 Top 3,节奏按上面 6 条规则的状态机推进;"演绎中"加载态(呼吸光晕 + "staging the scene…"),视频就绪后 crossfade 600ms 进场,说话者 step-forward + 提亮;老故事(从 Home 进)没有选角记录,以"自己"身份旁观
